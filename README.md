# 오성한의원 홈페이지

파주 봉일천 오성한의원의 GitHub Pages 정적 홈페이지입니다.

## 페이지

- `index.html`: 진료 분야, 빠른 방문 안내, 의료진 및 건강정보
- `about.html`: 의료진 소개
- `info.html`: 진료시간, 주소, 전화 및 길찾기
- `faq.html`: 기존 20개 질문과 검색·분류
- `health/`: 건강정보 목록과 칼럼

`style.css`는 공통 디자인과 홈, `pages.css`는 상세 페이지, `site.js`는 메뉴·FAQ·주소 복사를 담당합니다. 폰트는 `assets/fonts/`에서 제공하며 OFL 라이선스를 포함합니다. 별도 패키지 설치 없이 열 수 있고, `main`에 반영하면 GitHub Actions가 사이트맵과 RSS를 생성한 뒤 GitHub Pages에 배포합니다.

전화번호·주소·진료시간을 변경할 때는 각 페이지 공통 안내, JSON-LD, `llms.txt`의 정보도 함께 수정합니다.

## 검색엔진 수집 설정

`sitemap.xml`, `sitemap.txt`와 전체 사이트 RSS인 `rss.xml`은 실제 HTML 파일을 바탕으로 생성합니다. 세 파일은 같은 색인 대상 URL을 사용하며, 페이지 파일을 추가·삭제하면 다음 자동 배포에 함께 반영됩니다. 소유확인 HTML, 404 페이지, `noindex` 페이지, 리다이렉트 페이지, 다른 페이지를 canonical로 지정한 중복 페이지는 제외합니다. 칼럼의 XML 사이트맵 `lastmod`와 Article `dateModified`에는 글별 `website_modified`를 사용합니다. 나머지 페이지의 XML 사이트맵 `lastmod`는 해당 HTML 파일의 Git 수정일을 한국 날짜로 변환합니다.

`sitemap.txt`는 Google이 공식 지원하는 텍스트 형식으로, UTF-8 파일에 절대 URL을 한 줄씩 기록합니다. XML 사이트맵의 가져오기 오류를 조사할 때 별도 주소로 제출할 수 있도록 제공하며, 기존 XML 사이트맵과 RSS도 계속 유지합니다. 형식이나 주소를 추가하는 것만으로 Google의 가져오기·처리 성공이 보장되지는 않습니다. 공식 형식 안내: https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap?hl=ko#text

배포 시 최종 사이트맵 XML은 GitHub Pages가 지원하는 `jekyll-sitemap` 1.4.0(Jekyll 3.10.0)으로 생성합니다. 기존 Python 빌드에서 확인한 색인 대상 URL과 수정일을 임시 Jekyll 페이지의 메타데이터로 전달하고, 플러그인의 결과가 그 URL·수정일과 모두 일치할 때만 `sitemap.xml`로 사용합니다. Jekyll이 만든 HTML과 robots.txt는 사용하지 않으므로 홈페이지 화면과 수집 허용 설정은 기존 파일을 그대로 배포합니다. 플러그인은 사이트맵 생성 도구이며 Google의 수집·처리 성공을 보장하는 기능은 아닙니다.

플러그인의 디렉터리 주소 표기에 맞춰 건강칼럼 목록의 대표 주소는 `https://ohsunghani.github.io/health/`입니다. 목록 HTML의 canonical·Open Graph·CollectionPage URL과 사이트맵·RSS가 이 주소를 사용하며, 기존 `/health/index.html` 링크도 같은 목록에 계속 연결됩니다.

칼럼 구조화 데이터는 작성자 김태환(`Person`)과 발행기관 오성한의원(`Organization`)을 구분하며, 화면의 작성자·직책 표시와 같은 정보를 사용합니다. 추가 약력이나 검수 완료 표시는 넣지 않습니다. FAQ 구조화 데이터는 두 빌드 모드 모두 실제 `faq.html`의 질문과 답변에서 생성하므로, 별도의 답변 사본을 편집하지 않습니다.

로컬에서 검색 파일만 갱신하려면 다음 명령을 실행합니다. 이 모드는 기존 HTML 본문을 다시 생성하지 않습니다.

```sh
python3 scripts/build-health.py --search-only
```

배포와 같은 플러그인 결과까지 생성하려면 Ruby 3.3과 Bundler를 준비한 뒤 다음 명령을 추가로 실행합니다. 플러그인 의존성은 `Gemfile.lock`에 고정하며 GitHub Actions에서는 자동으로 설치·실행합니다.

```sh
bundle install
python3 scripts/build-jekyll-sitemap.py
```

정식 주소는 `https://ohsunghani.github.io/`입니다. Google Search Console과 네이버 서치어드바이저에도 같은 HTTPS 주소로 등록하고 `https://ohsunghani.github.io/sitemap.xml`을 제출합니다. Google Search Console에서는 추가로 `https://ohsunghani.github.io/sitemap.txt`를 제출할 수 있습니다. 네이버 RSS 제출 주소는 `https://ohsunghani.github.io/rss.xml`입니다. `robots.txt`는 전체 수집을 허용하며 XML·텍스트 사이트맵 주소를 안내합니다. Google·네이버 소유확인 파일은 삭제하지 않습니다.

## 건강칼럼 추가·수정

건강칼럼의 주된 원문은 오성한의원 네이버 블로그입니다. 새 글은 네이버 원문을 우선 활용하고, 티스토리는 보조·백업 자료로 사용합니다. 원문을 고를 때는 이미 발행한 칼럼과 주제가 겹치는지 확인합니다.

칼럼 발행은 블로그 원문을 요약·정리하는 작업입니다. 제목·소개·핵심 요약·소제목·본문 모두 원문에 실제로 있는 내용으로 구성합니다. 지역명과 문장은 다듬을 수 있지만, 원문을 다른 질문이나 주제로 바꾸거나 원문에 없는 조언·절차·사례를 만들어 넣지 않습니다. 외부 자료의 내용을 보태고 해당 블로그를 출처로 표시하지 않습니다.

발행 전에는 각 문장의 근거가 되는 원문 대목을 대조합니다. 짧은 원문은 과도하게 압축하지 않고, 원문에 있는 도입·설명·사례·마무리 맥락을 충분히 살려 홈페이지에서도 독립적으로 읽히게 정리합니다. 특히 ‘진료실에서 들은 말 하나’처럼 대화와 맥락이 중심인 글은 핵심 문장만 남기는 식으로 줄이지 않습니다. 분량이나 소제목 수를 맞추려고 원문 밖의 내용이나 반복 문장을 추가하지 않습니다. 확인되지 않은 치료효과나 보험 적용 내용을 옮기지 않고, 원문에서 다루는 범위 안에서 정리합니다. 본문 하단에는 실제 원문 제목·작성일·링크를 표시합니다.

티스토리와 네이버 원문에 같은 압축 비율을 적용하지 않습니다. 긴 티스토리 글은 충분히 줄이고, 짧은 네이버 글은 맥락을 더 살려 원문이 뒷받침하는 범위에서 최종 본문 분량이 비슷하게 읽히도록 맞춥니다. 2026-11-17에는 ‘진료실에서 들은 말 하나’ 원문을 사용한 나머지 43편을 본문 1,000자 이상으로 보완했습니다. 글자 수를 셀 때는 소제목과 본문을 합산하며, 제목·핵심 요약·출처·작성자·관련 글은 제외합니다.

발행 요청을 받으면 최신 글부터 검토하고, 2026년 이후 작성된 원문을 우선 활용합니다. 이전 연도 글은 적합한 최근 원문이 없을 때 보조적으로 검토합니다.

검진 사업의 무료 지원·모집 기간·운영 일정처럼 시점이 핵심인 과거 공지는 일반 건강칼럼으로 바꾸어 발행하지 않습니다. 원문 작성일은 실제 게시일이나 게시 타임스탬프로 확인하며, 상대적인 시간 표시 때문에 날짜를 누락하지 않습니다.

`philosophy`(진료 철학)는 네이버 블로그의 해당 카테고리(`categoryNo=25`, ‘오성한의원은 이렇게 진료합니다’)에 실제로 속한 원문만 사용합니다. 진료실 일화·시설 소개·다른 카테고리 글을 해석해 진료철학으로 바꾸지 않습니다. 제목뿐 아니라 원문의 주제와 취지를 유지하며, 티스토리 원문도 이 분류에는 사용하지 않습니다.

확인한 원문 목록과 제목·작성일은 `scripts/philosophy-sources.json`에 기록합니다. 새 진료철학 원문을 추가할 때는 네이버 카테고리 목록과 원문을 직접 확인한 뒤 이 목록을 갱신합니다. 전체 생성과 배포 시 검증을 통과하지 못하면 중단합니다.

`health/articles.json`에 제목·분류·소개·원문 출처·본문 소제목을 추가한 뒤 다음 명령을 실행합니다.

```sh
python3 scripts/build-health.py
```

건강정보 목록, 홈페이지의 최신 원문 3개 미리보기, 개별 칼럼, 함께 읽을 글, 사이트맵과 RSS를 함께 갱신합니다. 배포에는 생성된 HTML도 포함합니다. 별도 서버나 패키지 설치는 필요 없습니다. `airconditioner-shoulder.html`도 확인한 블로그 원문과 출처 정보를 바탕으로 다른 칼럼과 같은 방식으로 생성하며, 기존 주소를 유지합니다. 칼럼을 삭제할 때는 JSON 항목과 해당 HTML 파일을 함께 삭제합니다.

- `published_date`는 네이버 블로그 원문의 실제 작성일입니다. 알 수 없으면 `null`로 둡니다.
- 홈페이지에 처음 게시한 날은 `website_published`에 기록합니다. 맨 위 `updated`는 목록의 갱신일이며 개별 글의 수정일이 아닙니다.
- 개별 칼럼의 `website_modified`와 `content_digest`는 전체 빌드가 관리합니다. 제목·분류·소개·핵심 요약·본문·출처·게시일이 실제로 바뀐 글만 한국 날짜로 수정일을 갱신합니다. 다른 글 추가, 공통 작성자 메타데이터, 디자인 및 관련 글 갱신은 기존 글의 수정일을 바꾸지 않습니다. 두 필드를 임의로 갱신하지 말고 전체 빌드를 실행합니다. 배포 전 검색 파일 생성은 오래된 내용 해시가 있으면 중단합니다.
- 분류: `pain`(통증·자세), `accident`(교통사고), `treatment`(치료·내원 안내), `herbal`(한약·공진단), `lifestyle`(생활건강), `philosophy`(진료 철학).
- 블로그에서 정리한 글은 원문 제목과 주소를 유지합니다. 확인되지 않은 치료효과·경력·통계를 추가하지 않습니다.

목록의 검색과 분류는 `journal.js`, 칼럼 카드와 목록 스타일은 `journal.css`에서 관리합니다.

## 원문 전수 대조 기록

2026-11-15에 나머지 319편을 실제 블로그 원문과 대조했습니다. 원문과 일치하는 표현을 유지하고, 원문 밖의 주제 확장·사례·절차·조언을 덜어내거나 원래 주제로 되돌렸습니다. 앞서 수정한 11편은 보존했습니다. 원문에서 확인되지 않은 치료효과·보험 보장이나 단정적인 설명은 다른 내용으로 채우지 않고 생략했습니다.

대조한 출처의 제목·실제 작성일·수집된 원문 HTML의 SHA-256과 글별 수정 범위는 `scripts/audits/blog-source-audit-2026-11-15.json`에 기록합니다. 이 기록은 검색엔진 검증이나 의료적 효과의 입증을 뜻하지 않으며, 향후 새로 추가하거나 수정하는 문장은 그때의 실제 원문과 다시 대조해야 합니다.

2026-11-16에 기존 340편의 글별 수정일을 `health/articles.json`의 실제 내용 변경 Git 기록으로 복원했습니다. 당시 기준 커밋과 글별 근거는 `scripts/audits/article-revisions-2026-11-16.json`에 기록했습니다. 블로그 원문 작성일과 홈페이지 최초 게시일은 유지합니다.
